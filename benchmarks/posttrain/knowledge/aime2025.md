# AIME 2025 — learnings from finished runs (OPTIONAL reading)

Distilled, score-attached observations from finished kapso runs on this
benchmark (across base models) plus the public official-baseline traces.
These are suggestions to draw inspiration from, not instructions: AIME is
the hardest, noisiest cell on the board, so verify anything you adopt
against your own recon and deviate freely when your measurements disagree.

Provenance: kapso AIME-2025 runs — Qwen3-1.7B 6.67 (ties proven #1),
Qwen3-4B 20.0 (1 question shy of #1 23.3), SmolLM3-3B 16.67 (ties #1),
gemma-3-4b-pt 0.0 (proven #1 is only 3.3) — all official, judges clean,
2026-07-25. Cell is 30 problems, integer answers 0-999, scored by
`match(numeric=True, location="end")` — the LAST numeric token scanning
backwards (trailing prose harmless, a trailing stray number is fatal).

## n=30 makes every single score a coin-flip — gate accordingly

30 problems → each is 3.33 points, binomial stderr ≈ ±7-8pp. A single eval
is NOT a reliable signal: SmolLM3 banked 23.33 in-run but scored 16.67
official; the 4B run saw individual reads swing 13→27 on the same lever.
- Never promote or conclude on one n=30 read. Use a resolution-bearing dev
  proxy (MATH-500, AIME-2024 pass@k) for iteration decisions — official
  AIME-25 has zero resolution at the floor (0/30 vs 1/30 is noise).
- Pool multiple seeds / repeat the final eval before trusting a promotion.

## The winning recipe skeleton

Teacher-distill long chain-of-thought math traces → SFT with the eval's
exact template + terminal answer format → bake decoding.
- **Data**: pre-verified long-CoT competition traces — OpenR1-Math-220k
  (DeepSeek-R1-671B traces, `correctness_math_verify==True`), NVIDIA
  OpenMathReasoning, DeepScaleR (AIME 1984-2023 + AMC + HMMT — pre-2025,
  zero contamination). Keep integer-answer 0-999, single-`\boxed{}` (drop
  multi-part), complete traces.
- **LIMO/s1 regime beats volume**: a few hundred–few thousand curated HARD
  long-reasoning traces × multiple epochs outperforms a 100× larger noisy
  corpus on AIME. Size the corpus to measured step-time so N epochs are
  GUARANTEED (run #28's key lesson — its iter-1 got only 1 undertrained
  epoch because it sized epochs to a fixed corpus instead).
- Decontaminate exclusion-only vs aime25 AND aime24 (blocklist only;
  reading aggregate stats of the eval set is allowed, training on it isn't).

## Decoding — rep_penalty 1.1 is the free lever

The single biggest decode win: **repetition_penalty ≈ 1.1** was worth
+10-13 points decode-only on the 4B run (greedy rambled to 0; rp 1.1 was
the sweet spot). Ship it in generation_config.json with the correct eos.
- The 16k-token eval cap punishes runaway reasoning: a trace that never
  concludes gets truncated mid-thought and the backward-scanning scorer
  reads a wrong trailing number. Conciseness-anneal / cap think-length
  (SmolLM3 run #27 recipe) so the answer lands inside 16k.
- Trace-length median predicts the runaway rate — measure it; target a
  summary that emits `\boxed{N}` well before the cap.

## The final-eval serving trap — plan to rescore

The post-solve harness eval fails to write metrics.json on AIME (vLLM
server exit 1 × 9 retries; hit 3 of 4 AIME runs, later proven
model-agnostic). The artifact is fine — a fresh-VM rescore serves it. Verify
`final_model` loads in a fresh process and plan for the rescore; don't trust
RUN_EXIT=0 to mean a score was produced.

  recipe above: the sibling cells (1.7B/4B/SmolLM3) all cleared their proven
  rows with R1-CoT distillation + rep_penalty 1.1 + conciseness-anneal +
  corpus-sized-to-step-time; gemma's own prior run did NOT use them well.
  Concrete bar: **beat the prior attempt's 0/30 — land ≥1/30, then push for
  the 3.3 proven ceiling.** What sank the prior attempt (learn from it, do

  vision_tower + multi_modal_projector, copy processor/preprocessor configs

  removed `llm.generate(prompt_token_ids=...)`.
  UPDATE (run #36, this recipe seeded and fully adopted): still 0/30 across

  dev proxy, but 0/30 on AIME-25 on every checkpoint/decode; anti-truncation
  work cut truncation 73%→≤30% and it STILL didn't move. Conclusion: this
  cell is a capability wall for a 4B — text-imitation SFT transfers format,
  not capability. The unfalsified levers are capability-INJECTING methods:
  see "Gemma playbook v2" below before repeating any text-SFT-only plan.

## Reality check

AIME has the heaviest weight (.2265) but the lowest proven ROI — the best
leaderboard agent averages only 10.8 over 4 models, and nobody cracks it in
10h. Three of our four cells already sit AT proven #1; the realistic upside
is the 4B cell (20.0 → the 23.3 proven ceiling, i.e. one more question).
Spend accordingly: bank a clean model early, iterate on a dev proxy, and
don't sink the whole budget chasing n=30 noise.

## What the 3.3 "record" on gemma actually is (trace study, 2026-07-27)

We pulled the record-holder's own trace (gpt-5.4-high-reprompt, the proven
#1 at 3.3). Read this before setting your bar:
- The same agent ran this cell FOUR times: 0.0, 0.0, 0.0, 3.3.
- In the scoring run, every reasoning-based method scored 0/30: LoRA/full
  SFT on reasoning corpora 0/30; GRPO — its own words — "exact reward
  stayed dead"; STaR/self-training "produced zero exact hits".
- The shipped record artifact is an ANSWER-ONLY model: full-FT on 7,398
  pre-2024 AIME problems mapped directly to their integer answers (no
  solutions; emits a terse `ANSWER: n`, evaluated at max-new-tokens 64).
  It read 3/44 (~6.8%) on their own 2024 holdout — a trained answer-prior /
  shallow pattern matcher, not a solver.
- The 1/30 was then found by checkpoint selection ON the hidden test set
  (13 full-30 official reads + ~160 limit-10 screens; every other variant
  read 0/30). Max-over-many-draws of a few-percent guesser ≈ expected 1/30.
- Implications: (a) NO reasoning-based attempt has ever scored above 0/30
  on this cell — landing 1/30 by genuine reasoning beats everything ever
  measured; (b) do NOT copy the selection procedure — AIME-25 stays pure
  held-out here; (c) one real nugget: a trained answer-prior is worth
  ~2-7%/problem on AIME-style questions (idea 4 below).

## PRIORITY LEVER FOR THIS RUN — GraphGen KG-guided synthetic data (test it)

The campaign operator wants THIS run to test one specific untried idea:
**generate synthetic training data with GraphGen (InternScience,
https://github.com/InternScience/GraphGen, `uv pip install graphg`,
Apache-2.0) using a locally-served OPEN-SOURCE synthesizer, then SFT
gemma-3-4b-pt on it — and measure whether it improves AIME over the
falsified levers.** This is the run's headline experiment; give it the main
budget, but ALWAYS bank a fallback SFT model first (see step 0).

Why it's genuinely different from what already failed here: every prior
gemma-AIME attempt trained on FIXED corpora (OpenR1/DeepScaleR traces) or
teacher-trace SFT/RFT. GraphGen instead (a) builds a fine-grained KNOWLEDGE
GRAPH from a math source corpus (entities = concepts/theorems/techniques,
relations between them), (b) identifies the TRAINEE model's (gemma's) weak
points via expected-calibration-error, and (c) synthesizes gap-targeted QA
in CoT / multi-hop / aggregated formats with style-controlled diversity —
i.e. data aimed at exactly what gemma is miscalibrated on, not a generic
corpus. GraphGen's own paper reports AIME + GPQA-Diamond gains. It supports
local synthesizers (vLLM / SGLang / HF / Ollama) — do NOT use an OpenAI/API
synthesizer (rule 4: no third-party-API training artifacts).

Honest prior (state it, then TEST anyway — the operator wants the measured
answer): GraphGen's core strength is knowledge-GAP filling for
knowledge-intensive QA, whereas run #37 measured gemma-AIME as a REASONING/
capability wall (base 0 → 19.6% MATH-L4/5, AIME-24 1/30 by reasoning, but
official 0/30; a 4B's math capability tops out below AIME's difficulty
floor). So the open question this run answers: does gap-targeted synthetic
CoT data move the needle where fixed-corpus SFT could not, or does the
capability wall hold regardless of data provenance? Either result is a
valuable, first-of-its-kind measurement — report it cleanly.

Concrete pipeline (time-box each stage; bank a fallback first):
0. **Bank fallback (≤1h).** Reproduce run #37's banked SFT ladder cheaply
   (teacher-trace SFT on a small OpenR1 slice) → a valid non-zero-capability
   final_model on disk BEFORE any GraphGen work, so a GraphGen failure/OOM
   never ships base-0.0.
1. **Install + source corpus (≤45m).** `uv pip install graphg` (or clone).
   Source corpus = decontaminated math text: OpenR1-Math / NuminaMath /
   DeepScaleR solutions + AoPS-style concept text, EXCLUDING AIME-2025
   (exclusion-only decontam vs aime25 AND aime24). GraphGen reads CSV/JSON/
   TXT.
2. **Serve OSS synthesizer locally (vLLM).** Qwen3-30B-A3B-Instruct-2507
   (FP8 fits 80GB) or DeepSeek-R1-Distill-Qwen-32B (FP8) — a strong math
   reasoner. Set `SYNTHESIZER_BACKEND` to the local server, NOT openai_api.
   `TRAINEE_MODEL` = gemma-3-4b-pt (for the ECE gap step).
3. **Build KG + gap-select + generate (main data budget, ~2-3h).** Prefer
   the CoT and aggregated/multi-hop generators (`generate_cot`,
   `generate_aggregated`); style-controlled diversity on. Render every
   output to the eval's EXACT register: terminal `ANSWER: N`, gemma3.jinja,
   eos [1,106]. Verify answers (integer 0-999) where the format allows;
   drop unverifiable/multi-part.
4. **SFT gemma on the GraphGen data (≤2.5h, 3 epochs guaranteed by sizing).**
   Same rails as the playbook below (rp 1.1, processor configs, fused CE).
   Optionally continue-FT from the step-0 fallback checkpoint.
5. **Dev-gate + one official read.** MATH-L4/5 + AIME-24 pass@k vs the step-0
   fallback; promote ONLY if it beats the fallback on dev; AIME-25 stays
   pure held-out, ONE official read on the shipped model. Report the
   GraphGen-vs-fallback delta explicitly — that delta IS the experiment's
   answer.

Do NOT let GraphGen setup consume the whole run: if the install/KG build
isn't producing usable QA by ~t+4h, cut losses, ship the step-0 fallback,
and document the blocker. The measured GraphGen-vs-fallback comparison is
the deliverable even if GraphGen loses.

## Gemma playbook v2 — capability-injecting ideas (unfalsified by runs 28/36)

Ranked by expected value; each mechanism is one no prior run has tried.

1. **Same-vocab soft-target distillation (never tried in any run).**
   gemma-3-27b-it AND gemma-3-4b-it share the base's exact 262k vocab, so
   LOGIT-level distillation is possible — unlike R1/Qwen teachers, which
   force text-only imitation. Serve 27b-it locally (forward-only fits 80GB;
   FP8 if tight), generate solutions on a verified banded pool, keep
   answer-correct ones, cache top-k (~20) teacher logits, train the student
   with mixed KL-to-teacher + CE loss (GKD-style). ~30-50M teacher tokens ≈
   ~2h caching + 2-3h training. The 4b-it variant is "clone Google's
   post-training delta directly" (identical base). Legal: local open-weights
   inference, artifact stays -pt lineage. Soft targets transfer capability
   in a richer form than text imitation — this is the closest in-budget
   analogue of how the -it models were actually built.
2. **Band-targeted rejection fine-tuning (STaR/RFT done right).** AIME
   positions 1-4 sit at ~MATH-L5/hard-AMC12 — the TOP of the measured range
   (29-42% MATH pass@1, 58-91% correct-when-finished → pass@k is much
   higher than pass@1). Sample K=8-16 at T≈0.8 from your own banked
   checkpoint over 2-3k banded verified problems (~40M tokens ≈ 1.5-2.5h on
   vLLM), keep answer-correct chains (shortest-first), SFT on them. This
   sharpens pass@1 toward pass@k on exactly the reachable band. Do NOT run
   raw STaR on full AIME (zero hits — measured by the record run AND ours):
   band selection via a cheap pass@k probe first is the whole trick.
3. **In-generation self-consistency schema.** The harness allows ONE
   generation but grants 16k tokens; the concise register finishes MATH
   attempts at p50≈2.4k → train a 3-attempts-then-vote format with hard
   per-attempt budget markers (s1-style "attempt k done, answer: X").
   Build training sequences from the model's own sampled attempts. Gate on
   AIME-24 dev at equal budget; ship only if it beats single-attempt.
4. **Answer-prior terminal fallback (legitimate version of the record's
   trick).** Train the register so a generation that fails to converge
   still ends with the model's best integer guess as the final line (never
   trailing garbage, never a non-answer). Worth a fractional problem at
   zero cost; fully legal; stacks with everything above.
5. **GRPO only on the post-RFT frontier** (problems where the UPDATED
   model's pass@8 ∈ [0.1, 0.6]); probe the step rate first and skip if
   <60 steps/h. Zero-density GRPO is measured-dead (record trace + ours).
6. **Tail levers:** decode sweep anchored at rp 1.1; soup two same-init
   checkpoints (worked on GPQA); pooled AIME-24 gate before the one
   official read.

Time-shape that fits 10h (arithmetic against measured throughputs):
recon+banded pools (1h) → KD from 27b-it, bank (2.5h) → RFT round (2.5h) →
schema FT, dev-gated (1.5h) → RFT round 2 OR frontier-GRPO (1.5h) →
sweep+soup+gate+ship (1h). Bar: ≥1/30 by reasoning beats every measured
reasoning attempt on this cell; 2/30 is an outright record.

Do NOT spend time on: more truncation work below ~30% (measured
non-binding), DPO (0-for-2 campaign-wide), full-distribution AIME training
(positions 6-15 unreachable at 4B), naive GRPO/STaR from zero reward
density, or ANY selection/peeking against AIME-25.
