# AIME 2025 — learnings from finished runs (OPTIONAL reading)

Distilled, score-attached observations from finished kapso runs on this
benchmark (across base models) plus the public official-baseline traces.
These are suggestions to draw inspiration from, not instructions: AIME is
the hardest, noisiest cell on the board, so verify anything you adopt
against your own recon and deviate freely when your measurements disagree.

Provenance: kapso AIME-2025 runs — Qwen3-1.7B 6.67 (ties proven #1),
Qwen3-4B 20.0 (1 question shy of #1 23.3), SmolLM3-3B 16.67 (ties #1),
gemma-3-4b-pt 0.0 (proven #1 is only 3.3) — all official, judges clean,
2026-07-25. Cell is 30 problems, integer answers 0-999, scored by
`match(numeric=True, location="end")` — the LAST numeric token scanning
backwards (trailing prose harmless, a trailing stray number is fatal).

## n=30 makes every single score a coin-flip — gate accordingly

30 problems → each is 3.33 points, binomial stderr ≈ ±7-8pp. A single eval
is NOT a reliable signal: SmolLM3 banked 23.33 in-run but scored 16.67
official; the 4B run saw individual reads swing 13→27 on the same lever.
- Never promote or conclude on one n=30 read. Use a resolution-bearing dev
  proxy (MATH-500, AIME-2024 pass@k) for iteration decisions — official
  AIME-25 has zero resolution at the floor (0/30 vs 1/30 is noise).
- Pool multiple seeds / repeat the final eval before trusting a promotion.

## The winning recipe skeleton

Teacher-distill long chain-of-thought math traces → SFT with the eval's
exact template + terminal answer format → bake decoding.
- **Data**: pre-verified long-CoT competition traces — OpenR1-Math-220k
  (DeepSeek-R1-671B traces, `correctness_math_verify==True`), NVIDIA
  OpenMathReasoning, DeepScaleR (AIME 1984-2023 + AMC + HMMT — pre-2025,
  zero contamination). Keep integer-answer 0-999, single-`\boxed{}` (drop
  multi-part), complete traces.
- **LIMO/s1 regime beats volume**: a few hundred–few thousand curated HARD
  long-reasoning traces × multiple epochs outperforms a 100× larger noisy
  corpus on AIME. Size the corpus to measured step-time so N epochs are
  GUARANTEED (run #28's key lesson — its iter-1 got only 1 undertrained
  epoch because it sized epochs to a fixed corpus instead).
- Decontaminate exclusion-only vs aime25 AND aime24 (blocklist only;
  reading aggregate stats of the eval set is allowed, training on it isn't).

## Decoding — rep_penalty 1.1 is the free lever

The single biggest decode win: **repetition_penalty ≈ 1.1** was worth
+10-13 points decode-only on the 4B run (greedy rambled to 0; rp 1.1 was
the sweet spot). Ship it in generation_config.json with the correct eos.
- The 16k-token eval cap punishes runaway reasoning: a trace that never
  concludes gets truncated mid-thought and the backward-scanning scorer
  reads a wrong trailing number. Conciseness-anneal / cap think-length
  (SmolLM3 run #27 recipe) so the answer lands inside 16k.
- Trace-length median predicts the runaway rate — measure it; target a
  summary that emits `\boxed{N}` well before the cap.

## The final-eval serving trap — plan to rescore

The post-solve harness eval fails to write metrics.json on AIME (vLLM
server exit 1 × 9 retries; hit 3 of 4 AIME runs, later proven
model-agnostic). The artifact is fine — a fresh-VM rescore serves it. Verify
`final_model` loads in a fresh process and plan for the rescore; don't trust
RUN_EXIT=0 to mean a score was produced.

## Per-base-model notes

- Qwen3 bases: eos [151645, 151643]; the 4B is the most tractable (20.0,
  one question under proven #1) — rep-penalty decode forensics carried it.
  1.7B tops out around the proven 6.7 (tiny-model math ceiling).
- SmolLM3: eos [128012, 128001]; conciseness-anneal recipe reached 16.67
  (ties #1); watch the n=30 noise (banked 23.33 in-run).
- gemma-3-4b-pt: eos [1, 106]; the hardest cell — base 0.0, proven #1 only
  3.3, human 10.0. This is the base model that most needs the transferable
  recipe above: the sibling cells (1.7B/4B/SmolLM3) all cleared their proven
  rows with R1-CoT distillation + rep_penalty 1.1 + conciseness-anneal +
  corpus-sized-to-step-time; gemma's own prior run did NOT use them well.
  Concrete bar: **beat the prior attempt's 0/30 — land ≥1/30, then push for
  the 3.3 proven ceiling.** What sank the prior attempt (learn from it, do
  not repeat it): only 1 undertrained epoch (size the corpus to measured
  step-time so ≥3 epochs are guaranteed); a corpus skewed 79% off-register
  (filter to AIME-difficulty integer-answer traces); and no dev-proxy
  resolution (use MATH-500 / AIME-2024 pass@k — the prior run's MATH-500 hit
  0.41, so the pipeline works, the transfer is what needs the recipe).
  Arch traps to pre-empt (all cost the prior run time): multimodal — freeze
  vision_tower + multi_modal_projector, copy processor/preprocessor configs
  into every saved checkpoint (vLLM dies without them); pt ships NO
  generation_config (write one with eos [1,106] + rep_penalty 1.1); the 262k
  vocab OOMs fp32 logits at the loss step (use fused/chunked CE); vLLM 0.11
  removed `llm.generate(prompt_token_ids=...)`.

## Reality check

AIME has the heaviest weight (.2265) but the lowest proven ROI — the best
leaderboard agent averages only 10.8 over 4 models, and nobody cracks it in
10h. Three of our four cells already sit AT proven #1; the realistic upside
is the 4B cell (20.0 → the 23.3 proven ceiling, i.e. one more question).
Spend accordingly: bank a clean model early, iterate on a dev proxy, and
don't sink the whole budget chasing n=30 noise.
