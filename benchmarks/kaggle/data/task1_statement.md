# 🎧 Operation Night Watch: Teaching an Old Classifier New Sounds

*IOAI 2026 AI Models Track — Practice Task 1 (Kaggle code competition
`ioai-2026-ai-models-track-practice-task-1`, a.k.a. IOAI 2026 Home Task 1 —
Audio Classifier).*

Take a **deployed audio event classifier** and teach it to recognize **13
brand-new sound classes** — *without* destroying what the model already knows.

The production model is an **Audio Spectrogram Transformer (AST)**
(`ASTForAudioClassification`, 12 layers, hidden 768, 16-label head) trained on
16 everyday and wildlife sound classes. Two new customers need 13 new classes:
a national park detecting illegal logging/poaching activity (crackling fire,
axe, chainsaw, generator, hand saw, vehicle engine, helicopter, gunshot,
firework) and an entomology institute distinguishing four singing insects
(*Pterophylla camellifolia*, *Cicada orni*, *Gryllus campestris*, *Tettigonia
viridissima*). The upgraded model must keep serving the existing customers —
the 16 old classes must keep working too.

## Task rules (binding)

1. You **must start from the provided checkpoint** (`dataset/model/`) and
   reuse its encoder weights. You may add parameters (extra classifier rows,
   adapters, …) and fine-tune any subset of weights.
2. Your final model must classify **all 29 classes** (16 old + 13 new) in a
   **single forward pass**.
3. **No training from scratch, and no other pre-trained models of any kind**
   — no external weights, checkpoints, embeddings, LoRAs, foundation models;
   no libraries that auto-download pretrained resources; no external data
   (public/private/scraped/API-sourced); no external AI services or APIs
   anywhere in the solution.
4. ⏱️ Keep it lightweight: training must fit **a single GPU, ~10 minutes of
   training time** (reproducibility review can check this).

## Scoring

Held-out test set covering all 29 classes, single 29-way classification:

    Score = 0.5 * Acc_old + 0.5 * Acc_new

`Acc_old` = accuracy over test clips whose true label is one of the 16 old
classes; `Acc_new` = accuracy over the 13 new classes. Forgetting the old
classes costs exactly as much as failing to learn the new ones.

## Data (`dataset/`)

- `audio/` — 1,283 `.wav` clips (all splits' audio lives here).
- `train.csv` — 296 rows, base classes, labels 0–15
  (columns: path, split, target, category). Imbalanced: 3–62 rows/class.
- `fine_tune.csv` — 624 rows, new classes, labels 16–28 (24–60 rows/class).
- `submission.csv` — 363 evaluation rows (`path,target`): predict `target`
  for each referenced clip, keep the same columns and row order.
- `model/` — the provided AST checkpoint (`config.json`, `model.safetensors`,
  `preprocessor_config.json`; 128 mel bins, max_length 1024).

Class labels 0–28 in order: Dog, Rooster, Pig, Cow, Frog, Cat, Hen, Sheep,
Crow, Mouse Click, Keyboard Typing, Thunderstorm, Sea Waves, Bird Chirping,
Wolf Howl, Rain, Crackling Fire, Axe, Chainsaw, Generator, Hand Saw, Vehicle
Engine, Helicopter, Gunshot, Firework, Pterophylla Camellifolia, Cicada Orni,
Gryllus Campestris, Tettigonia Viridissima.

## Submission mechanics (Kaggle code competition)

- A valid submission is generated by a Kaggle kernel run (plain `.py`
  script is fine) with the competition attached as a data source; the
  kernel runs with **Internet OFF** on one GPU and writes `submission.csv`
  (same columns/row order as the reference file) itself.
- The kernel must reproduce the submission from the competition data +
  provided checkpoint alone — i.e. **train inside the kernel**
  (≤ ~10 GPU-minutes), then predict.
- Daily submission cap: **5 per day**.
