Give Kapso a goal it can measure and it runs a campaign: designing candidate solutions, implementing each one, scoring it, and refining the best. You get back the winning code, its score, and a git branch per experiment.

## Before you start

Kapso runs its inference through coding-agent CLIs, so confirm the machine is ready first:

```bash
kapso doctor evolve
```

Every required row must read `[OK ]`. If any does not, follow [Installation](/docs/installation) — the CLIs and their logins are the part people miss.

## Run a campaign

State a goal with a number in it. A goal Kapso cannot score is a goal it cannot optimize.

<Tabs>
  <Tab title="CLI">
    ```bash
    kapso evolve \
        --goal "Build a random forest classifier for the Iris dataset with accuracy > 0.9" \
        --iterations 10 \
        --output ./iris_solution
    ```
  </Tab>
  <Tab title="Python">
    ```python
    from kapso import Kapso

    kapso = Kapso()

    solution = kapso.evolve(
        goal="Build a random forest classifier for the Iris dataset with accuracy > 0.9",
        max_iterations=10,
        output_path="./iris_solution",
    )

    print(solution.explain())
    ```
  </Tab>
</Tabs>

The campaign stops when the goal is met or the iteration budget runs out.

<Tip>
  Bound the run by wall clock or spend instead of iterations with `--time-budget-minutes` and `--cost-budget`. Both are also `evolve()` keyword arguments.
</Tip>

## What you get back

`evolve()` returns a `SolutionResult`:

```python
solution.goal              # the goal you gave it
solution.code_path         # directory holding the winning code
solution.final_score       # score of the delivered solution
solution.succeeded         # whether the goal was met
solution.experiment_logs   # one summary per experiment
solution.final_feedback    # the last feedback, including the stop decision
solution.metadata          # cost, iteration count, final evaluation
solution.explain()         # all of the above as readable text
```

Every experiment is committed to its own branch, so you can read the whole search, not just the winner:

```bash
cd ./iris_solution
git branch -a
```

```text
  generic_exp_0
  generic_exp_1
* generic_exp_2
  main
```

## Deploy the result

```python
from kapso import Kapso, DeployStrategy

deployed = kapso.deploy(solution, strategy=DeployStrategy.LOCAL)
result = deployed.run({"data_path": "./test.csv"})
deployed.stop()
```

`DeployStrategy` accepts `AUTO` (the default, which picks for you), `LOCAL`, `DOCKER`, `MODAL`, `BENTOML` and `LANGGRAPH`. See [Deployment](/docs/deployment/overview).

## Give the campaign more to work with

A campaign starts stronger when it starts with context. Both of these are optional.

### Research the problem first

```python
findings = kapso.research(
    "QLoRA fine-tuning memory optimizations",
    mode=["idea", "implementation"],
    depth="deep",
)

solution = kapso.evolve(
    goal="Fine-tune Llama-3.1-8B with QLoRA, target eval loss < 0.5",
    context=[findings.to_string()],
    output_path="./qlora_v1",
)
```

`mode` takes `"idea"`, `"implementation"`, `"study"`, or a list of them. `depth` is `"light"` or `"deep"`.

### Ground it in a knowledge graph

Index a corpus once, then point campaigns at the index:

```python
kapso = Kapso()
kapso.index_kg(
    wiki_dir="data/wikis",
    save_to="data/indexes/finetuning.index",
)
```

```python
kapso = Kapso(kg_index="data/indexes/finetuning.index")
```

Indexing needs Weaviate and Neo4j running. See [Optional: knowledge-graph backends](/docs/installation#optional-knowledge-graph-backends).
