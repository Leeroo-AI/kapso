Everything public is importable from the top-level `kapso` package.

```python
from kapso import Kapso, Brief, Budget, Solution, Source, Software

kapso = Kapso()
```

## Constructor

```python
Kapso(
    config: str | None = None,
    bank: str | None = None,
)
```

| Argument | What it does | Default |
|----------|--------------|---------|
| `config` | Path to a config file: the engine's knobs, nothing else. Nothing starts here | the packaged `config.yaml` |
| `bank` | Your bank's home directory, where `learn()` writes and `mine` is served from. Overrides `learning.bank.local_path` | from config |

| Method | Returns | What it does |
|--------|---------|--------------|

## load_harness

Loads a [harness](/docs/harnesses): the domain's pages, skills, tool
servers, delegates and hooks, staged into every session of the verbs that
follow.

```python
load_harness(ref: str) -> Harness
```

| Argument | What it does |
|----------|--------------|
| `ref` | A bundled name (`predictive-modelling`), a directory (`./harnesses/trading`, read from the working directory), or a git reference (`git+https://github.com/acme/harnesses@v3#trading`, `acme/harnesses@v3#trading`) |

```python
harness = kapso.load_harness("../harnesses/trading")
harness.name, harness.version, harness.hash, harness.source   # the identity every record carries
harness.missing                                               # what this machine lacks, [] when nothing
kapso.harness                                                 # the same object, or None
```

It resolves the reference, fetching a git one into the store, runs `check` and raises `HarnessError` on a failure, hashes the directory, and reads what this machine lacks into `missing` without raising. A second call replaces the first: one object, one harness. Nothing starts here. The forms, the checks and the handle are in the [harness reference](/docs/reference/harness).

`build()` uses the loaded harness over the brief's `Harness` line, and refuses before any session while a need of the build's modules is unmet. `deploy()` and `learn()` take the harness from the solution's record when none is loaded; a loaded one of the same name is used instead, another version included; another name is refused.

## load_experience

Loads a source a build is served, what was measured before: your own
bank (the one `learn()` writes), the hosted Leeroopedia gate, a bank you
read, or a corpus ingested under a name. See [Experience](/docs/experience).

```python
load_experience(ref: str) -> ExperienceSource
share_experience(url: str) -> None
```

| Argument | What it does |
|----------|--------------|
| `ref` | `mine` (your bank, the cards whose scope covers the loaded harness) or `mine:all` (every card you measured); `leeroopedia` (the hosted gate, its key in `.env`); a bank home by path (`./bank.git`, which must exist); a bank repository by git reference (`acme/kapso-bank`, `acme/kapso-bank@v2`, `git+https://…@main`); or the name of an ingested index (`org-x`). A bank you read, the hosted gate and an index serve everything they hold |

```python
source = kapso.load_experience("mine")
source.kind, source.resolved, source.head, source.provenance   # "bank", "/home/me/.kapso/bank.git", "3f9c…", "measured by you"
kapso.experience                                               # the loaded sources, in load order
kapso.share_experience("https://github.com/acme/kapso-bank.git")
```

Loading resolves the reference, confirms the source exists and is readable (a bank's format, the hosted gate's key, an index's record), pins it as it is on disk (a bank at its head, an index at its id; loading never pulls), prints one line and appends it to the object's sources; a reference loaded again replaces its entry. Loading never ingests and never creates: a source that does not exist is refused with the `kapso experience add` line that makes it. `build()` serves the loaded sources, which win over the brief's `Experience` line as the loaded harness wins over its `Harness` line; with nothing loaded, a fresh build loads the brief's items, and a resume takes the launch's list at its pins. `share_experience` attaches a git remote to your bank and pushes it, creating the bank first when there is none; `learn()` pushes there from then on, and the intro says the cards are measured by you and your team.

## add_experience

Makes a source that must exist before it can be loaded, and returns its reference.

```python
add_experience(ref: str | None = None, *, repo: str | None = None, research: str | None = None, name: str | None = None) -> str
```

| Argument | What it does |
|----------|--------------|
| `ref` | `mine` creates your bank, empty (a first `learn()` does too); `leeroopedia` checks the hosted gate's key is present |
| `repo` | A repository URL to ingest into a new index named `name` |
| `research` | A question to research on the web; the findings are ingested into a new index named `name` |
| `name` | The index's name: letters, digits and dashes; `mine` and `leeroopedia` are reserved |

Exactly one of `ref`, `repo` and `research` is given. Ingesting runs the knowledge pipeline into the experience home (`experience.indexes` in the config): the pages under `<name>/wiki/`, the index's own namespace in the graph stores, and `index.json`, the record that pins the index at its id and names what it was made from. An index is never written again after this: a name that exists is refused (remove it first). The stores and the embeddings key are checked before any work (`kapso doctor experience`); the operation writes a status file you can `kapso watch`.

```python
kapso.add_experience(repo="https://github.com/org/x", name="org-x")
kapso.add_experience(research="QLoRA memory optimizations", name="qlora")
kapso.load_experience("org-x")        # a build then mounts the search gates over it
```

## update_experience and remove_experience

Loading never touches the network beyond a first fetch; these two do the rest.

```python
update_experience(ref: str | None = None) -> None
remove_experience(ref: str) -> None
```

`update_experience` is the network step: `mine` takes its remote's main (fast-forward; a history that does not is an error in git's words), a bank you read at a branch or `HEAD` is fetched again, a tag or a commit never moves; with no `ref` every bank on this machine is updated. A running campaign keeps the pin it launched with. An index is what `add_experience` made: remove it and add it again. `remove_experience` deletes what `load` fetched or `add` made — a bank you read by git reference (its clone and record), or an index by name (its backend namespace, its pages and its record) — and refuses the rest: your bank is yours, the hosted gate is a key in `.env`, a bank by path is read in place.

```python
kapso.update_experience()                      # every bank
kapso.update_experience("acme/kapso-bank")     # one
kapso.remove_experience("org-x")
```

## build

Runs the experiment campaign: propose a candidate, implement it on its own
branch, measure it, keep the best, repeat until the objective is met or the
budget is spent.

```python
build(
    brief: str | Brief | None = None,
    *,
    evaluation: str | None = None,
    data: str | None = None,
    repo: str | None = None,
    output: str | None = None,
    budget: Budget | None = None,
    resume: bool = False,
    on_status = None,
    iteration_evaluator: IterationEvaluator | None = None,
    iteration_evaluator_failure_policy: str = "record",
    coding_agent: str | None = None,
    detach: bool = False,
) -> Solution | Launch
```

| Argument | What it does | Default |
|----------|--------------|---------|
| `brief` | A sentence, or a `Brief`. A sentence becomes a brief with only an objective. The whole brief reaches the engine, never clipped. Left out only on a resume, which takes it from the checkpoint | `None` |
| `evaluation` | Directory holding your evaluator; copied to `kapso_evaluation/` and protected | `None` |
| `data` | Directory holding your data; copied to `kapso_datasets/` | `None` |
| `repo` | The starting repository: a local path (copied, never modified) or a GitHub URL (cloned). `None` starts empty, or from a workflow the knowledge graph knows | `None` |
| `output` | The campaign directory, the solution's `trace`. Empty for a fresh build; the campaign itself for a resume | a temporary directory |
| `budget` | What the build may spend. Its set fields win over the brief's `Budget` line; on a resume the launch record fills what is still unset; the config's defaults fill the rest | `None` |
| `resume` | Continue the campaign in `output` from its checkpoint. The host, evaluation, config and experience must match the launch's; a difference is refused by name | `False` |
| `on_status` | Callback fired after every status write and heartbeat | `None` |
| `iteration_evaluator` | Score every finalized candidate with your own evaluator, in an isolated worktree | `None` |
| `iteration_evaluator_failure_policy` | `record` stores your evaluator's error on the candidate; `raise` stops the run | `"record"` |
| `coding_agent` | The host every role without a `cli` of its own runs on, with that host's model: an entry of the config's `hosts` table. Recorded and fingerprinted, so a resume runs on the launch's host | `search_strategy.params.host` |
| `detach` | Launch the campaign in a session of its own and return a [`Launch`](#launch) at once: `kapso build --detach` from Python. Needs `output`; takes no in-process callback; the harness and experience loaded on this instance go with it | `False` |

```python
solution = kapso.build(
    Brief.read("kapso-brief.md"),
    evaluation="evaluation", data="data", repo=".",
    output="../churn-build", budget=Budget(minutes=60),
)
print(solution.explain())
```

`build()` blocks for the whole campaign and writes the solution to
`<output>/.kapso/solution.json` when it returns, so
[`Solution.open`](#solution) reads it from any process. To leave it running,
pass `detach=True`: the campaign starts in a session of its own and a
[`Launch`](#launch) comes back at once, the same launch as `kapso build
--detach`.

```python
launch = kapso.build(Brief.read("kapso-brief.md"), repo=".", output="../churn-build", detach=True)
print(launch.pid, launch.log)      # follow it: kapso watch ../churn-build --follow
```

### Launch

What `build(detach=True)` and `learn(detach=True)` hand back at once.

| Field | What it is |
|---|---|
| `pid` | The session's process id |
| `log` | The log the session writes, beside the campaign (`<output>.log`, `<campaign>.learn.log`) |
| `status` | What to follow: a build's `<output>/.kapso/status.json`, a learn's status directory (`kapso watch <status> --follow`) |

The work goes on after your process ends; `Solution.open(output)` reads a
build's result once it has one.

### Brief

The brief as an object; the same grammar as the `kapso-brief.md` file. See
the [brief format](/docs/reference/brief-format).

```python
@dataclass
class Brief:
    objective: str
    measured_by: str | None = None
    baseline: str | None = None
    target: str | None = None
    rules: list[str] = []
    budget: Budget | None = None
    harness: str | None = None
    experience: list[str] = []

Brief.read(path) -> Brief        # parse the file; an unknown or repeated field, a missing
                                 # objective or stray text raises BriefError with the line
Brief.parse(text) -> Brief
brief.render() -> str            # the file's text, deterministic: what the engine receives
brief.write(path) -> Path
```

### Budget

```python
@dataclass
class Budget:
    minutes: float | None = None           # wall clock, durable across resumes
    experiments: int | None = None         # experiments this call may run
    usd: float | None = None               # model spend, USD
    reserve_minutes: float | None = None   # kept out of the search for finishing the last attempt and delivering
```

Every field optional; a field left `None` keeps the brief's, the launch's
or the config's value. Values are validated: positive and finite, an
integer count, a reserve smaller than the minutes.

### Solution

What a build delivered and the account of how. Returned by `build()` and
read back by `Solution.open(path)`.

| Attribute | Type | What it holds |
|-----------|------|---------------|
| `brief` | `Brief` | The brief the build ran |
| `campaign` | `Path` | The campaign directory, checked out at the delivered branch, with the record under `.kapso/` |
| `branch` | `str \| None` | The delivered candidate's branch; `None` when no candidate succeeded |
| `commit` | `str \| None` | Its commit at delivery |
| `base_commit` | `str` | The seed commit, `diff()`'s base |
| `score` | `float \| None` | The delivered candidate's measurement under the registered evaluator |
| `goal_achieved` | `bool` | The judge's verdict that the objective was met |
| `stopped_reason` | `str` | `goal_achieved`, `max_iterations`, `budget_exhausted`, `waiting_for_user` |
| `stop_detail` | `str \| None` | Why a budget stop happened: `time_budget`, `cost_budget`, `attempt_would_not_fit` or `finishing_cut`; see [Resume and budgets](/docs/build/resume-and-budgets#how-a-campaign-ends) |
| `experiments`, `experiments_total` | `int` | Experiments this call, and across every resume |
| `cost_usd` | `float` | Model spend |
| `requests` | `list[dict]` | What you must answer when `stopped_reason` is `waiting_for_user`; empty otherwise |
| `feedback` | `str \| None` | The last judgment, in full |
| `evaluator` | `EvaluatorRef \| None` | `version`, `evaluator_id`, `provenance` of the evaluator the score was measured under; `None` when none was registered |
| `harness` | `HarnessRef \| None` | `name`, `version`, `hash`, `source` of the harness the build ran with; `None` without one |
| `verification` | `dict \| None` | The harness's verdict on the delivered candidate: `verdict`, `summary`, `findings`; `None` when no verification ran |
| `experience` | `list[ExperienceRef]` | What the build was served, in load order: each source's `reference`, `kind` (`bank`, `hosted`, `index`), `resolved` location, pinned `head`, `provenance` and `scope`; empty when nothing was loaded |
| `rejected_candidates` | `int` | Candidates rejected: the judge found the evaluation invalid, the evaluator was touched, or the harness voided the attempt |
| `callback_metrics`, `callback_primary_metric` | `dict`, `str \| None` | Your own `iteration_evaluator`'s numbers for the delivered candidate |
| `session_failures` | `list[dict]` | The sessions' runs that ended `error`, `timeout` or `refused`, each `{label, module, host, exit, error}`; `explain()` prints them as `Sessions failed:` after the experiments line |

```python
Solution.open(path) -> Solution   # the record a build wrote in that directory;
                                  # raises before the build has returned, naming kapso watch
solution.explain() -> str         # the summary block
solution.diff() -> str            # git diff from the seed to the delivered commit; "" when none
```

### inbox and reply

A campaign pauses when a session needs something only you can provide; see
[the inbox](/docs/build/inbox). Four methods act on a paused campaign
directory.

```python
Kapso.inbox(campaign: str) -> list[Request]
Kapso.awaiting_resume(campaign: str) -> list[Request]
Kapso.inbox_ideas(campaign: str) -> dict[int, str]
Kapso.reply(campaign: str, request_id: int, note: str = "", *, allow_secret: bool = False) -> Solution | None
```

`inbox` returns the open requests, oldest first, each with `id`, `key`, `hit`, `tried`, `fix` and `next_steps`. `awaiting_resume` returns the answered requests a resume has not delivered, because the last one failed or was killed, and is empty while a live process holds the campaign. `inbox_ideas` returns one line per node of the campaign, the idea a request was made for, keyed by node id; `kapso inbox` prints it as the `for` row. `reply` records the note and, once every request of the node that asked is answered, resumes the campaign in this process and returns its result. It returns `None` when another request of that node is still open, or when the campaign was started with an `iteration_evaluator`: the callback lives in your script, so call `build()` again there with `resume=True`. It raises while a live process holds the campaign, and raises on a note shaped like a credential unless `allow_secret=True`: replies are plain text handed to the coder, so a value belongs in the `.env` the request's `fix` names. A resume that fails raises with the answer kept: call `reply` again to retry, with a note to replace the answer or an empty one to keep it.

## learn

Learns from one finished campaign: import it, mine it, grade the bank against it, then fold the result in as evidence-priced cards.

```python
learn(
    source: Solution | str,
    *,
    trajectory_id: str | None = None,
    learner_version: str | None = None,
    exam: bool = True,
    push: bool | None = None,
    on_status = None,
    detach: bool = False,
) -> LessonResult | Launch
```

| Argument | What it does | Default |
|----------|--------------|---------|
| `source` | A `Solution` (its `trace` is read directly), a path to a campaign directory, or a trajectory id already in the store | required |
| `trajectory_id` | Store id when importing a directory | derived from the objective or directory name |
| `learner_version` | Update-crew version | `learning.update_crew.default_version` |
| `exam` | Run the hindcast exam against the pinned pre-lesson bank head first. `False` is for development replays only | `True` |
| `push` | Push the bank commit to the bank's `origin` remote | auto: pushes when the bank has an `origin` remote |
| `on_status` | Callback fired on each status heartbeat | `None` |
| `detach` | Run the learn in a session of its own and return a [`Launch`](#launch) at once: `kapso learn <campaign> --detach` from Python. The campaign form only: no trajectory id, learner version, exam, push or callback | `False` |

```python
lesson = kapso.learn(solution)
print(lesson.explain())
```

On a campaign built with a harness, the learning module is staged into the mining and update crews' sessions, the update crew's codex workers included (the pages in each prompt; the skills, servers, delegates and hooks beside each session, in its host's format), and the trajectory manifest records the build's harness and, when it differs, the one the lesson ran with.

### LessonResult

| Attribute | Type | What it holds |
|-----------|------|---------------|
| `trajectory_id` | `str` | Id of the trajectory that was learned from |
| `bank_head_after` | `str` | Bank commit written by this lesson |
| `cards_created` | `list[str]` | New cards the update crew wrote |
| `cards_updated` | `list[str]` | Existing cards the lesson modified |
| `exam_report_path` | `str \| None` | Hindcast exam report, when `exam=True` |
| `lesson_report_path` | `str \| None` | The lesson report |
| `admitted` | `bool` | Whether the lesson was admitted to the bank |
| `explain()` | `str` | The above as readable text |

## deploy

```python
deploy(
    solution: Solution,
    target: str | None = None,
    env: dict[str, str] | None = None,
    options: dict[str, str] | None = None,
    coding_agent: str | None = None,
) -> Software
```

| Argument | What it does | Default |
|----------|--------------|---------|
| `solution` | The `Solution` from `build()`, or `Solution.open(path)`; its campaign checked out at the delivered candidate, tracked files unchanged | required |
| `target` | `auto` (the session chooses), a bundled target (`local`, `docker`, `modal`, `bentoml`, `langgraph`) or a target the build's harness ships | from config (`deployment.target`) |
| `env` | Variables the software needs at runtime: written to `.env` in the deployment's workspace, named (never valued) in the prompt, set on every runtime the engine manages | `None` |
| `options` | Options for the target's workflow, exported to its scripts as `KAPSO_OPTION_<NAME>` | `None` |
| `coding_agent` | The host the deployment session runs on | from config (`deployment.cli`, else the build's host) |

```python
software = kapso.deploy(solution, target="docker", env={"API_KEY": "..."})
result = software.run({"tenure_months": 3, "plan": "basic"})   # software.proof["inputs"] is the example
software.stop()
Software.open("../churn-build", software.number).start()      # the same deployment, from any process
```

A `DeployError` names what refused the deployment (no such target, a dirty campaign, a result the engine could not accept, a session that failed) and the record's path. On a solution built with a harness, the session carries its deployment module (the page, the skills, servers and hooks) beside the target's skill. See [Deploy](/docs/deploy/targets).

### Software

| Member | What it does |
|--------|--------------|
| `run(inputs)`, `software(inputs)` | One call, by the deployment's run kind: `{"status": "success", "output": …}` or `{"status": "error", "error": …}`; refused while the deployment is not running |
| `run_batch(inputs_list)` | `run` over each, in order |
| `stop()`, `start()` | The target's stop and start scripts (a function's worker ended or started); the state written to the record; each returns the lines it noted, which `logs()` repeats |
| `is_healthy()` | Running by the record and answering its health check (a function: its worker answers a ping) |
| `close()` | This handle's worker ended, the deployment left running |
| `logs()` | The engine's lines, the target's logs script, a function's worker log |
| `number`, `state`, `target`, `endpoint`, `workspace`, `record`, `proof`, `observed` | The record's facts; `proof` is the call the session proved, what `run()` takes, `observed` what the engine's own call of it answered; `target` is `None` when a session under `auto` chose none |
| `Software.open(campaign, number=None, config=None)` | The campaign's deployment of that number, or its highest, whatever its state |
| `with kapso.deploy(...) as software:` | `stop()` on exit |

## status

A static method. Reading a run needs no constructed agent.

```python
Kapso.status(path: str) -> OperationStatusView
```

```python
view = Kapso.status("./campaign")
print(view.explain())
```

`path` accepts a workspace, a status file, or a directory of status files. `view.explain()` renders the same screen as [`kapso watch`](/docs/reference/cli#kapso-watch).

## trace

A static method, a pure reader: the campaign's record after the fact, what [`kapso trace`](/docs/reference/cli#kapso-trace) prints.

```python
Kapso.trace(path: str) -> TraceView
```

```python
view = Kapso.trace("./campaign")
print(view.explain())                       # the text, every section
view.data                                   # the JSON, the keys pinned on Read the record
view.attempts                               # one entry per node: sessions, runs, evaluation, verification, judge, cards
view.delivered                              # the delivered candidate; None when none succeeded
print(view.narrow("generic_exp_1").explain())   # one attempt with its evidence in full
```

`TraceView(data)` renders the text again from the data alone. A campaign still running renders `partial` with the reason; a directory with no `.kapso/` inside raises `FileNotFoundError` by name; `narrow` raises `ValueError` naming the attempts when no attempt ran on the branch. See [Read the record](/docs/build/trace).

## close

Releases the index search's network clients: Weaviate, Neo4j and embeddings, connected when a build loads an index.

```python
kapso.close()
```

Idempotent, and registered at construction to run on exit, so scripts finish without unclosed-socket warnings. Calling it early is safe; the next build that loads an index reconnects.
