Kapso reads one YAML file of its own, the packaged `config.yaml`, and one of yours over it. Every tunable value lives in those two layers, and nothing is configured through environment variables.

## Two layers, one file of yours

The packaged file carries every default. Your file carries only what you change, and is layered over it: nested mappings merge key by key, scalars and lists replace.

```yaml
# kapso-config.yaml: an override file. Everything not named here is the packaged value.
hosts:
  codex:
    model: gpt-5.6-sol
search_strategy:
  params:
    host: codex              # every role without a cli of its own runs on codex
    ideation:
      cli: claude_code       # ideation on Claude Code, with its host's model
budget:
  minutes: 90
```

```bash
kapso build --config kapso-config.yaml --brief kapso-brief.md --output campaign
kapso doctor --config kapso-config.yaml --show-config     # the effective config, as YAML
```

```python
from kapso import Kapso

kapso = Kapso()                                 # the packaged defaults
kapso = Kapso(config="kapso-config.yaml")       # yours over them
```

Nothing is read from the working directory unnamed: a config is passed with `--config` or `config=`, or the packaged defaults apply. `kapso doctor` prints which layers a run uses on its first line, `config: packaged defaults + kapso-config.yaml (overrides: search_strategy.params.host, hosts.codex.model)`, and `kapso doctor --json` carries the effective config under `config` and the dotted paths your file sets under `overrides`.

**The packaged file is the schema.** At every depth, a mapping in your file may name only the keys the packaged mapping names at that path. A key it does not name is refused by name, with the keys that exist:

```text
kapso-config.yaml: budget: unknown key minute; the keys are checkpoint_heartbeat_seconds, experiments, fidelity, …
```

A value the packaged file holds as a mapping must be a mapping in yours. The exceptions are the open namespaces, where your keys are your own: the entries of `hosts`, the roles under `inference.roles`, the servers under `gates`, `knowledge_search.params`, `search_strategy.params.session_env_defaults`, and the items of lists (an ensemble member, a lane's environment). One top-level key is reserved and never read by the engine: `benchmark`, a benchmark runner's own settings; the runners' files under `benchmarks/` are override files in this sense.

<Note>
  Configuration and credentials are separate. Knobs — models, budgets, timeouts, gates — come from these files. Credentials never do: the coding-agent CLIs hold their own logins, and keys such as `OPENAI_API_KEY` are read from `.env` by the SDKs that need them.
</Note>

## hosts

```yaml
hosts:
  claude_code:
    model: claude-opus-5
    auth_mode: oauth
  codex:
    model: gpt-5.6-sol
    effort: xhigh
```

A host is a coding-agent CLI a build may run sessions on. Each entry names the `model` the host is asked for, an `effort` where the adapter takes one, and the adapter's own settings: the keys `agents.yaml` lists under the adapter's `settings`.

| Host | Settings it takes |
|------|-------------------|
| `claude_code` | `auth_mode` (`oauth` uses the CLI's stored login, `api_key` uses `ANTHROPIC_API_KEY`, `auto` takes either, never Bedrock; `bedrock` runs against Amazon Bedrock), `aws_region` (required with `bedrock`, read from the config only) |
| `codex` | none beyond `model` and `effort` |
| `oss_claude_code` | `base_url`, `auth_token_env` |
| `vertex_claude_code` | `vertex_project`, `vertex_location`, `bridge_startup_timeout` |

These four are the adapters with a staging for a build session (`agents.yaml` names it under `host`); the others (`gemini`, `openhands`, `aider`, `openai_compatible`) have none, so `hosts.gemini: {model: …}` is refused with the hosts a build runs on. Within the four the entries are an open namespace: a host is added by naming it. A setting the adapter does not list is refused by name. A host must be able to serve its model: `codex` serves everything but `claude-*` models, `claude_code` serves `claude-*` and nothing else, and the preflight refuses the pair before a session runs (`kapso doctor build` shows the rows). The adapters themselves are on [Coding agents](/docs/evolve/coding-agents).

A host no role names is never asked for: `hosts` is a table, not a session source.

## search_strategy

```yaml
search_strategy:
  type: generic
  params:
    host: claude_code            # the default host: every role without a cli of its own
    ideation:
      cli: null                  # the role's own host; null takes `host`
      model: null                # null takes the host's model
      effort: null               # null takes the host's effort
      timeout: null              # seconds; null is no deadline beyond the budget's clamp
      gates: [research, experiment_history, repo_memory]
      web: true
      candidates_per_member: 1
      ensemble: null
      selector: null
      lens_planner: null
      ensemble_time_split: null
    implementation:
      cli: null
      model: null
      effort: null
      timeout: null
      gates: [research, repo_memory]
      web: true
      fallback_model: null
    judge:
      cli: null
      model: null
      effort: null
      timeout: null
    gate_failure_policy: warn
    honor_agent_stop: true
    parent_policy: best
    parent_sampling:
      temperature: 1.0
      offspring_penalty: 1.0
      seed: 0
    node_expansion_value: 1
    expansion_lane_env: null
    env_strip: []
    session_env_defaults: {}
    shared_cache_dir: null
    registered_evaluation_archive_glob: null
    repo_memory_failure_policy: warn
    repo_memory_max_retries: 1
    repo_memory_update_payload_max_chars: 400000
    cost:
      enabled: false
      estimator: null
      cap_per_candidate: null
      campaign_budget: null
      unit: credits
      weight: 0.0
```

### The roles

Three roles name the build's sessions. **Ideation** proposes candidates; **implementation** writes the code, and the verification session, the harness setup session and the difficulties reconstruction run on its host too; the **judge** is the feedback session that judges every attempt. Each role resolves the same way: its `cli`, else `params.host`; its `model`, else the host entry's; its `effort`, else the host entry's; the host entry's other keys as the session's settings. A role naming a host the table lacks is refused: `search_strategy.params.judge.cli: gemini is not in hosts (the hosts are claude_code, codex); add hosts.gemini: {model: …} to the config to use it`.

`kapso build --coding-agent <cli>` (Python: `build(coding_agent=)`) sets `params.host` for the campaign: the default host for every role without a `cli` of its own, with that host's model. It is recorded in the launch record as `host` and fingerprinted by the checkpoint, so a resume runs on the host the launch did.

| Key | What it does |
|-----|--------------|
| `<role>.timeout` | The session's deadline in seconds. Every session is also clamped by the budget: a search session against the searchable remainder, a finishing session against what its obligations leave (see [the budget](#budget)). `null` is no deadline beyond that clamp |
| `<role>.gates` | The bundled MCP gates the session mounts: `research` (the web), `experiment_history` (past attempts), `repo_memory`. A loaded bank or index mounts its own gate when it is loaded, never from a list. The judge mounts none |
| `<role>.web` | The native web tools, Claude Code's `WebSearch` and `WebFetch` and Codex's web search (`--search`, and the cached search the CLI runs without the flag, disabled by config): the engine's permission boundary on both hosts. Off, the tools leave the session. The ensemble members, the selector and the lens planner follow ideation's switch. A harness whose protocol forbids the web on a module lists a hook there as well; see [the harness reference](/docs/reference/harness#files) |
| `ideation.candidates_per_member` | Candidates each member is asked for. With one member and one candidate no selector runs |
| `ideation.ensemble` | Parallel members, `[{cli, model, effort, lens}, …]`, each a spec of its own over the hosts table (`model` and `effort` optional, the host's where unset). Their candidates are pooled by the selector |
| `ideation.selector` | `{cli, model, effort}`: the session that ranks the pool. Required when the pool holds more than one candidate |
| `ideation.lens_planner` | `{cli, model, effort, timeout}`: the session that designs each member's lens per iteration and names the design axes the judge reports on |
| `ideation.ensemble_time_split` | `{member_fraction, selector_fraction, selector_min_seconds}`: how the ideation clamp is carved between the members and the selector. Absent, each takes the whole clamp |
| `implementation.fallback_model` | A second model tried once when an implementation session crashes (a provider's safety kill). `null` retries nothing |
| `gate_failure_policy` | A gate the machine cannot serve: `warn` continues and says so, `skip` continues silently, `error` stops |
| `honor_agent_stop` | Whether the judge's stop vote ends the campaign: `true` for a task with a goal to reach; `false` for open-ended maximisation, where the vote is advisory and the budget is the only clock (the benchmark override files set it) |
| `parent_policy` | The branch a new attempt starts from: `best` (the champion), `baseline` (`main`) or `weighted` (a scored candidate sampled by rank, down-weighted by the children it already has). See [Parent selection](/docs/evolve/parent-selection) |
| `parent_sampling.temperature` | Positive; lower approaches `best`, higher approaches uniform. Used by `weighted` |
| `parent_sampling.offspring_penalty` | Non-negative; down-weights parents that already have children. Used by `weighted` |
| `parent_sampling.seed` | The `weighted` sampler's seed, so a resumed campaign draws the parent it would have drawn uninterrupted |
| `node_expansion_value`, `expansion_lane_env` | Parallel implementation lanes per iteration (the selector ranks that many candidates), and one `{VAR: value}` mapping per lane pinning its environment. Above one lane the inbox is off for the campaign |
| `env_strip`, `session_env_defaults` | Variables stripped from every session's environment, and set-if-absent defaults for every session (an open namespace) |
| `shared_cache_dir` | A cache the sessions share across the campaign; `null` keeps it under the campaign |
| `registered_evaluation_archive_glob` | Where a registered evaluation's archived runs are recovered from; `null` recovers nothing |
| `repo_memory_failure_policy`, `repo_memory_max_retries` | The repo memory's failure policy (`warn` or `fail`) and its retries |
| `repo_memory_update_payload_max_chars` | Characters of line-numbered changed-file text one repo-memory update call carries; past it the update is windowed into several calls of whole files |
| `cost.*` | Platform cost, separate from model spend: `enabled`, the module-qualified `estimator` (required when enabled), `cap_per_candidate` and `campaign_budget` in `unit` (`null` is unlimited), the selection `weight`. See [Cost-aware selection](/docs/evolve/cost-aware-selection) |

A parameter this block does not name is refused by name: the strategy reads a known set, and a typo never silently keeps a default. The ensemble shape the benchmarks run, as an override:

```yaml
search_strategy:
  params:
    host: codex
    ideation:
      candidates_per_member: 3
      ensemble:
        - {cli: codex, effort: xhigh}
        - {cli: claude_code, model: claude-fable-5, effort: xhigh}
      lens_planner: {cli: claude_code, model: claude-fable-5, effort: max, timeout: 600}
      selector: {cli: codex, effort: xhigh}
    implementation:
      web: false
      timeout: 18000
```

Turning the gates off is an override file too, not a second configuration:

```yaml
search_strategy:
  params:
    ideation:
      gates: []
    implementation:
      gates: []
```

## budget

```yaml
budget:
  experiments: 10
  minutes: null
  usd: null
  reserve_minutes: null
  min_iteration_seconds: 60
  min_agent_timeout_seconds: 60
  judge_reserve_seconds: 300
  checkpoint_heartbeat_seconds: 60
  stop_grace_seconds: 10
  fidelity:
    mode: "off"
    committed_run_fraction: 0.45
    min_affordable_full_runs: 4
    promotion_margin: 0.02
    max_full_runs: 2
    max_full_evals: 3
    calibration_min_pairs: 3
    endgame_validate: true
    build:
      fast_fraction: null
    eval:
      fast_fraction: 0.15
```

The first four keys are the `Budget` handle's words: the brief's `Budget` line wins over them, a call's `budget=` or `--budget-*` flag over the brief's. See [Resume and budgets](/docs/build/resume-and-budgets) for how the dials resolve and how a campaign ends.

| Key | What it does | Shipped value |
|-----|--------------|---------------|
| `experiments` | The experiment cap when neither the brief nor the call names one | `10` |
| `minutes` | The wall clock; `null` is unbounded | `null` |
| `usd` | The model spend, best effort; `null` is unbounded | `null` |
| `reserve_minutes` | Kept out of the search for finishing: the last attempt's evaluation, verification and judgment run inside it, and the delivery after them. `null` derives it each round from those obligations; a number wins; either is bounded by a quarter of the budget | `null` |
| `min_iteration_seconds` | The admission floor: a round starts only when the searchable remainder covers the larger of this and the previous round's own duration | `60` |
| `min_agent_timeout_seconds` | Below this a session cannot do useful work: a session whose deadline would be clamped under it is not launched, and says so | `60` |
| `judge_reserve_seconds` | What the judge is kept before one has been observed in the campaign: the round's reserve for it and the obligation the evaluation and the verification leave standing, so a first attempt's verification cannot run the remainder down to the floor and lose the attempt unjudged; a judge that has been observed is kept its own last duration | `300` |
| `stop_grace_seconds` | `kapso build --output <campaign> --stop`: how long the campaign's processes get after SIGTERM before SIGKILL ends them | `10` |
| `checkpoint_heartbeat_seconds` | How often a run refreshes its durable clock and status file | `60` |
| `fidelity.*` | Budget-aware fidelity: `mode` (`off` runs every attempt at full fidelity; `on` or `auto` need the maintainer), the fraction escrowed for the committed full-size run, the probe policy, the fast fractions. See [Evaluation integrity](/docs/evolve/evaluation-integrity) | `off` |

## inbox

```yaml
inbox:
  enabled: true
  stop_grace_seconds: 120
  registry: "~/.kapso/campaigns.jsonl"
```

| Key | What it does | Shipped value |
|-----|--------------|---------------|
| `enabled` | Let a blocked session ask you through the inbox and pause the campaign. See [the inbox](/docs/build/inbox) | `true` |
| `stop_grace_seconds` | How long a session that asked gets to end its own turn before the adapter ends it | `120` |
| `registry` | One line per launched campaign, so `kapso inbox` outside a campaign can list every one that waits | `~/.kapso/campaigns.jsonl` |

The benchmark override files set `enabled: false`: nobody is at the keyboard. The block is part of the checkpoint's fingerprint, so a resume never flips it silently.

## evaluation_maintainer

```yaml
evaluation_maintainer:
  enabled: false
  cli: null
  model: null
  effort: null
  timeout: null
  subsample_seed: 1337
  calibration_fraction: 0.03
  calibration_timeout_seconds: 900
  fast_variant_threshold_minutes: 20
  overhead_factor: 1.25
  max_change_requests: 3
  transition_freeze_fraction: 0.85
  protected_data_paths: []
```

Off by default. On, its sessions calibrate and register the evaluator a build measures with and protect it file by file; `cli`, `model`, `effort` and `timeout` name its session the way a role does, the build's host where unset. The calibration keys shape the fast-fidelity run; `max_change_requests` caps the evaluator change requests a campaign may file, and past `transition_freeze_fraction` of the time budget they are deferred, since a ruler change near the deadline orphans the final selection. See [Evaluation integrity](/docs/evolve/evaluation-integrity).

## inference

Routes model calls that are not coding-agent work: research, reranking and utilities.

```yaml
inference:
  default:
    cli: codex
    model: gpt-5.6-sol
    effort: xhigh
    sandbox: read-only
    timeout_seconds: 900
    web_search: false
  roles:
    research: {web_search: true, timeout_seconds: 1800}
    kg_rerank: {effort: low, timeout_seconds: 300}
    kg_navigate: {effort: low, timeout_seconds: 300}
    repo_memory: {}
    commit_message: {effort: low, timeout_seconds: 180}
    benchmark_utility: {effort: low, timeout_seconds: 600}
```

| Key under `default` | What it does | Shipped value |
|---------------------|--------------|---------------|
| `cli` | Which CLI runs the call | `codex` |
| `model` | Model that CLI is asked for | `gpt-5.6-sol` |
| `effort` | Reasoning effort | `xhigh` |
| `sandbox` | Filesystem access granted to the call | `read-only` |
| `timeout_seconds` | Per-call timeout | `900` |
| `web_search` | Whether the call carries the live-web tool | `false` |

`roles` overrides `default` for one named role, and is an open namespace. Anything a role omits falls back to `default`, so `kg_rerank` above keeps `cli: codex` and only lowers effort and timeout. A build's own inference sessions (the repo-memory bootstrap, the commit messages) are recorded under the campaign's `.kapso/sessions/engine/<role>/`.

| Role | Purpose | Overrides |
|------|---------|-----------|
| `research` | Deep web research | `web_search: true`, 1800s |
| `kg_rerank` | Rerank knowledge-graph hits | `effort: low`, 300s |
| `kg_navigate` | Navigate the graph | `effort: low`, 300s |
| `repo_memory` | Build repository memory | none, inherits `default` |
| `commit_message` | Write experiment commit messages | `effort: low`, 180s |
| `benchmark_utility` | Benchmark helper calls | `effort: low`, 600s |

## preflight

```yaml
preflight:
  enabled: true
  live_model_probe: false
```

| Key | What it does | Shipped value |
|-----|--------------|---------------|
| `enabled` | Run requirement checks before a verb starts | `true` |
| `live_model_probe` | Also fire a one-token live call per CLI and model pair | `false` |

These are the same checks [`kapso doctor`](/docs/reference/cli#kapso-doctor) reports, derived from the effective config: an all-codex build is never asked for `claude`. Leaving `enabled: true` is what makes a missing CLI fail in seconds instead of deep inside a run.

## gates

```yaml
gates:
  leeroopedia:
    url: "https://mcp.leeroopedia.com/mcp?token={LEEROOPEDIA_API_KEY}"
    tool_timeout_seconds: 600
```

The hosted MCP gates (see [MCP gates](/docs/evolve/mcp-gates)), an open namespace. Bundled gates run in-process and have no entry here.

| Key | What it does | Shipped value |
|-----|--------------|---------------|
| `url` | The server's streamable-HTTP address. A `{VAR}` placeholder is filled from the gate's required environment variable when a session launches, so the key rides on the URL without ever being written into the config or the campaign tree | `https://mcp.leeroopedia.com/mcp?token={LEEROOPEDIA_API_KEY}` |
| `tool_timeout_seconds` | How long a session waits on one tool call. Both CLIs default to 60 seconds, which cuts off Leeroopedia's agentic tools (`build_plan`, `verify_code_math`) mid-answer | `600` |

## deployment

```yaml
deployment:
  target: auto
  cli: null
  model: null
  effort: null
  timeout: 1800
  call_timeout: 300
  script_timeout: 600
  port_base: 8000
  port_span: 1000
```

The session `deploy()` runs, a spec over the hosts table in the shape of the build's roles, with the target it deploys to when the call names none, the deadlines and the ports. See [Deploy](/docs/deploy/targets).

| Key | What it does | Shipped value |
|-----|--------------|---------------|
| `target` | Where `deploy()` deploys when the call names no target: `auto` (the session chooses among the targets available), a bundled target or a harness's | `auto` |
| `cli` | The host the deployment session runs on, an entry of `hosts`; null follows the build's host, `search_strategy.params.host`, so a project that moves to Codex changes one key | `null` |
| `model`, `effort` | The host entry's when null | `null` |
| `timeout` | The deployment session's deadline, in seconds, its one resume included | `1800` |
| `call_timeout` | One `run()` call of the deployed software, in seconds | `300` |
| `script_timeout` | One lifecycle script of the target (start, stop, health, logs), in seconds | `600` |
| `port_base`, `port_span` | The host ports a deployment takes: the first free from `port_base + (hash + number) % port_span`, within the span | `8000`, `1000` |

`deploy(target=..., coding_agent=...)` and `kapso deploy --target --coding-agent` override per call. The two call deadlines must be positive finite numbers (`timeout` may be null: no deadline on the session), and the port range must stay within 1..65535.

## harness

```yaml
harness:
  store: ~/.kapso/harnesses
  page_warning_lines: 40
  setup_minutes: 20
  verification_minutes: 10
  verification_attempts: 2
  server_tool_timeout_seconds: 600
```

| Key | What it does | Shipped value |
|-----|--------------|---------------|
| `store` | Where a harness named by git reference is fetched, one directory per repository and revision | `~/.kapso/harnesses` |
| `page_warning_lines` | `kapso harness check` warns on an instruction page longer than this; pages go into every prompt of their module whole | `40` |
| `setup_minutes` | The harness setup session's timeout, clamped by the campaign's budget | `20` |
| `verification_minutes` | Each verification session's timeout, clamped the same way at each attempt; what the derived reserve keeps for verification | `10` |
| `verification_attempts` | How many sessions run for one attempt before it is recorded `unverified` | `2` |
| `server_tool_timeout_seconds` | How long a session waits on one call to a harness server, where the host takes a per-server timeout (Codex) | `600` |

See [Harnesses](/docs/harnesses). A harness is never named in the config: it is named on the build, in the brief, or in Python.

## experience

```yaml
experience:
  banks: ~/.kapso/experience/banks
  indexes: ~/.kapso/experience/indexes
  research_modes: [idea, implementation]
  research_depth: deep
  session_sources: []
```

| Key | What it does | Shipped value |
|-----|--------------|---------------|
| `banks` | Banks you read, one clone per `<slug>@<rev>` with a fetch record beside | `~/.kapso/experience/banks` |
| `indexes` | Corpora you ingested with `kapso experience add --name <n>`, one directory each | `~/.kapso/experience/indexes` |
| `research_modes`, `research_depth` | What a research ingest answers in (`idea`, `implementation`, `study`) and how deep it searches (`light`, `deep`) | `[idea, implementation]`, `deep` |
| `session_sources` | What a host session (`kapso-mcp`, the plugin's server) is served when `--experience` is absent: references in the grammar `kapso experience list` shows. A listed source that does not exist leaves its gate off, named in the server's instructions; `kapso learn` offers `[mine:all]`. A build loads what its brief or `--experience` names, never this list | `[]` |

Your own bank is `learning.bank.local_path`; the hosted gate is `gates.leeroopedia`. See [Experience](/docs/experience).

## knowledge_search

```yaml
knowledge_search:
  type: kg_graph_search
  preset: DEFAULT
  params: {}
```

| Key | What it does |
|-----|--------------|
| `type` | `kg_graph_search`, hybrid vector and graph search over the index a build loads; `kg_llm_navigation` remains registered for a benchmark's JSON graph |
| `preset` | Named retrieval preset: `DEFAULT`, `FAST`, `RERANK_ONLY` |
| `params` | An open namespace: the stores' endpoints (`weaviate_url`, `weaviate_grpc_port`, `neo4j_uri`, `neo4j_user`), the embedding provider and model (`openai` with `text-embedding-3-large`, or `vertex` with `vertex_project` and `vertex_location`), `use_llm_reranker`. `embedding_base_url` is a config-only endpoint for OpenAI embeddings: HTTPS, except for loopback hosts |

An index records the endpoints and the embedding model it was built with, so a build that loads it reaches the same stores and embeds queries the same way. See [Add a source](/docs/experience/add).

## learner

Two sub-blocks, `ingestor` and `merger`, the sessions `kapso experience add --repo` and `--research` run to build an index. Both take a `cli`, a `model`, an `auth_mode`, an `effort` and a `timeout` (shipped: `claude_code`, `claude-opus-5-5`, `oauth`, `xhigh`, `null`), plus an `agent_specific` map (shipped empty) that is passed to the agent. `cli` names the coding agent that runs the sessions: `claude_code` with the first-party login that `auth_mode` selects, or `vertex_claude_code` for an open model on Vertex AI, whose settings (`vertex_project`, `vertex_location`) go in `agent_specific`; on that agent `effort` is applied as the open model's `reasoning_effort` (Vertex accepts `minimal` to `max` for GLM 5.2; `xhigh` is sent as `max`); see [Coding Agents](/docs/evolve/coding-agents#vertex-ai-claude-code). `effort` is the reasoning effort of every learning session, pinned here so a session never inherits the effort from the machine's own Claude settings. `timeout` is a deadline in seconds; `null`, the default, means a phase runs until it finishes. `ingestor` additionally takes `cleanup`, `cleanup_staging`, `fail_on_validation_errors`, `publish_workflows` and `github_repo_visibility`. `publish_workflows` (off by default) publishes each extracted Workflow as a runnable GitHub repository after the pages have been validated; `gh` authenticates with `GH_TOKEN`, which the preflight requires when publishing is on. Off, a Workflow page keeps a placeholder in its GitHub URL section. A failed phase stops the run: an add raises rather than returning a partial index as a success. A run stages its clone, phase reports and pages under the index's `wiki/_staging/` and marks each finished phase, so a run that stopped continues from the first unfinished phase when the same source is added again under the same name; `cleanup` removes the clone once a run completes, `cleanup_staging` the whole directory. Learning sessions hold five file tools (Read, Write, Edit, Glob, Grep) plus the knowledge tools and nothing else, so they cannot run commands, reach the network or delegate; only the publishing session also gets Bash, for `git` and `gh`.

## retry

```yaml
retry:
  max_attempts: 2
  initial_delay_seconds: 5
  max_delay_seconds: 60
  multiplier: 2
  jitter: true
  request_timeout_seconds: 600
```

Bounded exponential backoff for transient model failures, and the hard per-request wall clock handed to the provider client. See [Model routing and retries](/docs/evolve/model-routing-retries).

## models

```yaml
models:
  embedding: null
```

The OpenAI embedding model for semantic search over past experiments (`search_similar_experiments`). `null` turns it off: the experiment store is recency-only and no `OPENAI_API_KEY` is needed. Set it (for example `text-embedding-3-small`) to turn it on; `kapso doctor build` then checks for the key.

## learning

Everything about trajectory learning: mining finished campaigns into an evidence-priced lesson bank.

| Key | What it controls |
|-----|------------------|
| `trajectory_store` | `local` path and optional `remote` for imported campaigns |
| `bank` | `local_path` of the bank repository |
| `serving` | `session_root`, where `kapso-mcp` stages a host session's sources (one directory per process, removed when the server exits) |
| `retriever` | `probe_budget` for lesson retrieval |
| `harvest` | Whether finished campaigns are harvested automatically |
| `mining` | How trajectories are mined into their derived views (the crew's models, `timeout_minutes`, `repair_rounds`), and `run_root`, where a mining run keeps its session's harness record and stream |
| `graders` | The grader suite settings |
| `update_crew` | The crew that folds lessons in: roles, repair rounds, timeouts |
| `codify` | The codify pipeline |
| `develop` | The development regime |
| `behavior` | Behavior scenarios |
| `ab` | A/B arm settings |
| `import_report_dir` | Where import reports are written |
| `status_dir` | Where status files are written |

Shipped values worth knowing:

```yaml
learning:
  trajectory_store:
    local: ~/.kapso/trajectories
    remote: null
  bank:
    local_path: ~/.kapso/bank.git
  serving:
    session_root: ~/.kapso/serving
  mining:
    run_root: learning/mining
  update_crew:
    default_version: crew_v4
    run_root: learning/runs
```

The store and the bank are Kapso's own state and live under `~/.kapso`, outside the project you run from, so a campaign's `--data-dir` and seed copy never pick them up.

<Warning>
  There is no serving switch. A campaign or a host session reads from the bank exactly when the bank is loaded (`load_experience("mine")`, `kapso-mcp --experience mine`); banked lessons have no effect on a `build()` that loads nothing.
</Warning>

`update_crew.default_version` is the version [`learn()`](/docs/reference/kapso-api#learn) uses when you do not pass `learner_version`.
