Kapso builds software for goals you can measure.

Give it a goal. It runs **experiment campaigns**: designing candidates, implementing them, scoring each one, and refining the best. Every claim of progress is a score, and the winner ships to your infrastructure.

The factory is **self-improving** because it learns from its own work. Finished campaigns become evidence-priced lessons. It also learns from public knowledge, including repositories and papers. Everything compounds in one knowledge hub, so each campaign starts where the last one left off.

## The four pillars

<CardGroup cols={2}>
  <Card title="Evolve" icon="dna" href="/docs/evolve/overview">
    **`.evolve()`** runs iterative experiments to build software for a goal, using tree search, coding agents and knowledge-graph context.
  </Card>
  <Card title="Learn" icon="brain" href="/docs/knowledge/overview">
    Two memories. **`.learn()`** mines your own finished campaigns into evidence-priced lesson cards. **`.learn_knowledge()`** ingests repositories and research into the knowledge graph.
  </Card>
  <Card title="Research" icon="magnifying-glass" href="/docs/research/overview">
    **`.research()`** runs deep web research and returns structured findings you can feed into the knowledge base or pass as campaign context.
  </Card>
  <Card title="Deploy" icon="rocket" href="/docs/deployment/overview">
    **`.deploy()`** turns a solution into running software, locally, in Docker, or on a cloud platform such as Modal.
  </Card>
</CardGroup>

## What a full run looks like

```python
from kapso import Kapso, Source, DeployStrategy

kapso = Kapso(kg_index="data/indexes/legal_contracts.index")

# Research the problem space
findings = kapso.research(
    "RLHF and DPO fine-tuning for legal contract analysis",
    mode=["idea", "implementation"],
    depth="deep",
)

# Fold public knowledge into the knowledge graph
kapso.learn_knowledge(
    Source.Repo("https://github.com/huggingface/trl"),
    findings,
    wiki_dir="data/wikis",
)

# Run the campaign
solution = kapso.evolve(
    goal=(
        "Fine-tune Llama-3.1-8B on the CUAD dataset for legal clause risk "
        "classification, target F1 > 0.85 on high-risk clause detection"
    ),
    context=[findings.to_string()],
    output_path="./models/legal_risk_v1",
)

# Bank what the campaign learned, so the next one starts ahead
kapso.learn(solution)

# Ship it
deployed = kapso.deploy(solution, strategy=DeployStrategy.MODAL)
```

<Note>
  `learn()` and `learn_knowledge()` are different memories and are easy to confuse. `learn()` takes a finished campaign and mines it into lesson cards. `learn_knowledge()` takes outside sources — repositories, research findings — and folds them into the knowledge graph.
</Note>

## What is inside

| Component | What it does |
|-----------|--------------|
| `Kapso` | The public API. Coordinates research, learning, evolution and deployment |
| Orchestrator | Runs the experiment loop and tracks the budget |
| Search strategy | Explores candidate solutions as a tree |
| Coding agents | Pluggable implementers: Claude Code, Codex, Gemini, OpenHands, OSS Claude Code |
| Feedback generator | Validates each evaluation and decides when to stop |
| Lesson bank | Evidence-priced cards mined from finished campaigns |
| Knowledge graph | Repository and research knowledge, searched over Weaviate and Neo4j |
| Repo memory | Evidence-backed understanding of an existing codebase |
| Deployment | Local, Docker, Modal, BentoML and LangGraph targets |

## Leeroopedia MCP

Kapso connects to [Leeroopedia](https://leeroopedia.com), a curated knowledge base of ML and AI frameworks. Agents query it during ideation and implementation to look up APIs, build plans and diagnose failures. See [Optional: Leeroopedia MCP](/docs/installation#optional-leeroopedia-mcp).
