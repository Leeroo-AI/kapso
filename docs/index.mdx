Kapso is an open-source engine that runs experiments, deploys the best solution, and learns from every run. It starts from a domain harness and an empty bank of lessons, and given an objective and success criteria it:

- **runs a tree of experiments**: proposes hypotheses, then implements and verifies each one;
- **deploys the best solution** on the target stack;
- **learns from the run**: credit goes to each hypothesis and implementation by its impact on the outcome, and the bank is updated, every lesson carrying a credence score and a boundary on where it applies.

Over time the domain harness carries a bank of lessons: the experimented best practices of that environment. Kapso is model-agnostic and coding-agent-agnostic.

Four parts, in the order a run meets them: smart experimentation, learning, deployment, and domain adaptation through a harness. Each is a section below and a verb on the `Kapso` object.

Kapso is open source, by [Leeroo](https://leeroo.com). The source lives at [github.com/Leeroo-AI/kapso](https://github.com/Leeroo-AI/kapso) and the package installs with `pip install leeroo-kapso`.

## The whole thing in twelve lines

```python
from kapso import Kapso, Brief, Budget, Solution

kapso = Kapso()                                      # engine knobs from the packaged config
solution = kapso.build(
    Brief.read("kapso-brief.md"),                    # objective, how it is measured, baseline, target, rules
    evaluation="evaluation", data="data", repo=".",  # your evaluator (protected), your data, your code
    output="../churn-build", budget=Budget(minutes=60),
)
solution.score, solution.branch, solution.diff()     # what was delivered, how it measured, what changed
software = kapso.deploy(solution)                    # running software, locally or on a target
lesson = kapso.learn(solution)                       # what the campaign taught, banked with evidence
Solution.open("../churn-build")                      # the same solution, from any process
```

The same from a shell: `kapso build --brief kapso-brief.md --evaluation evaluation --data data --repo . --output ../churn-build --detach`, then `kapso watch ../churn-build --follow`. [Your first build](/docs/first-build) runs it on the churn example.

## The four parts

<CardGroup cols={2}>
  <Card title="Smart experimentation" icon="hammer" href="/docs/build/brief">
    **`build()`** runs a tree of experiments: each node records the hypothesis, the implementation on its own branch, the budget used and the distance to the objective. For each experiment, an ideation module proposes ideas from earlier experiments and the bank of lessons, re-ranks them by expected return against the budget each would use, and sends the top-ranked ones to the implementor; a fingerprinted evaluator that no experiment can access verifies the result, and the modules can propose updates to the metrics and criteria for the verifier to approve. When a session needs a credential or a file only you can provide, the campaign asks and pauses until you reply.
  </Card>
  <Card title="Learning" icon="brain" href="/docs/learn/what-learn-produces">
    **`learn()`** turns a finished run into lessons: each is induced or deduced from the run's traces, carries a credence score, a boundary on where it applies and its evidence, and is updated from its effect on the outcome; every change to the bank is A/B tested by running the same build with and without it, so an improvement is measured, not guessed. **`load_experience()`** names what the next build is served: your bank, a bank your team shares, Leeroopedia, or a corpus **`add_experience()`** ingested from a repository or a researched question. The bank is built on git, so `kapso experience share`, `list` and `update` pass it around.
  </Card>
  <Card title="Deployment" icon="rocket" href="/docs/deploy/targets">
    **`deploy()`** runs a shorter experimentation of the same kind to adapt the best solution to the target stack: a session adapts a copy of the node, deploys it, and demonstrates health checks and a working call. Docker, Modal, BentoCloud and LangGraph Platform ship; a harness adds a target.
  </Card>
  <Card title="Domain adaptation" icon="puzzle-piece" href="/docs/harnesses">
    A harness is Kapso's domain package: the knowledge and workflows of an area such as predictive modelling, so a build does not experiment and learn from scratch. A run starts from a domain harness and an empty bank of lessons, and over time the harness carries the bank that accumulated what worked in that environment. Write your initial domain harness, your instructions, code, guardrails and checks, with `/kapso:harness` in the plugin or `kapso harness` in the CLI.
  </Card>
</CardGroup>

<Note>
  `learn()` mines your own finished campaigns into your bank; `add_experience()` ingests outside sources into an index. A build is served exactly what it loads.
</Note>

## What is inside

| Component | What it does |
|-----------|--------------|
| `Kapso` | The public API: `build`, `deploy`, `learn`, and the knowledge verbs |
| `Brief`, `Budget`, `Solution` | What a build takes and what it hands back, as objects and as files |
| Harness | The domain layer a build loads: pages, skills, tool servers, delegates and hooks, staged into every session |
| Orchestrator | Runs the experimentation and tracks the budget |
| Search strategy | Explores candidate solutions as a tree |
| Coding agents | Pluggable implementers: Claude Code, Codex, Gemini, OpenHands, OSS Claude Code |
| Feedback generator | Validates each evaluation against the brief and decides when to stop |
| Evaluation registry | The evaluator versions a campaign measured with, provided or built, protected |
| Bank of lessons | Lessons mined from finished runs, each with a credence score, a boundary and its evidence |
| Knowledge graph | Repository and research knowledge, searched over Weaviate and Neo4j |
| Repo memory | Evidence-backed understanding of an existing codebase |
| Deployment | Local, Docker, Modal, BentoML and LangGraph targets |

## Leeroopedia MCP

Kapso connects to [Leeroopedia](https://leeroopedia.com), a wiki of our lessons in the data and ML domains: around 100k pages extracted by experimenting on papers and repositories, serving about 6M requests a month, around 28% of them from AI agents. Agents query it during ideation and implementation to look up APIs, build plans and diagnose failures. See [Connect Leeroopedia](/docs/installation#connect-leeroopedia-recommended).
