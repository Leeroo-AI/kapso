A coding agent is what actually writes the code during an experiment. Kapso drives them as subprocesses through a common interface, so the agent is a config choice rather than something the rest of the system knows about.

## Which agents can I use?

| Agent | Description | Default model | Install |
|-------|-------------|---------------|---------|
| `claude_code` | Anthropic Claude Code CLI, for complex refactoring and planning | `claude-opus-4-5` (registry; both shipped modes override to `claude-opus-5`) | `npm install -g @anthropic-ai/claude-code` |
| `codex` | OpenAI Codex CLI, non-interactive exec with a full-access sandbox | `gpt-5.6-sol` | `npm install -g @openai/codex` |
| `gemini` | Google Gemini SDK, code generation with file parsing | `gemini-2.5-flash` | `pip install google-generativeai` |
| `openhands` | OpenHands agent SDK with a sandboxed execution environment | `gpt-4.1-mini` | `pip install openhands-ai litellm` |
| `oss_claude_code` | Claude Code CLI driven by an OSS model over an Anthropic-compatible endpoint | `glm-5p2` | `npm install -g @anthropic-ai/claude-code` |
| `aider` | Git-centric diff-based editing. Legacy, and needs Python 3.12 or older | — | `pip install "leeroo-kapso[aider]"` |

Both shipped config modes, `GENERIC` and `MINIMAL`, set `coding_agent.type: claude_code`, so that is the agent you get unless you override it.

An agent is only registered if its dependencies import, so `aider` is absent from a default install and `kapso --list-agents` shows five. Run that command to see what is actually available on your machine — it prints each registered agent with its description, default model, install command and the environment variables it reads:

```bash
kapso --list-agents
```

## Agent interface

All agents implement `CodingAgentInterface`:

```python
class CodingAgentInterface(ABC):
    def initialize(self, workspace: str) -> None:
        """Initialize for a specific workspace."""

    def generate_code(
        self,
        prompt: str,
        debug_mode: bool = False,
        timeout_seconds: Optional[float] = None,
    ) -> CodingResult:
        """Generate or modify code; timeout_seconds is the budget deadline."""

    def cleanup(self) -> None:
        """Clean up resources."""

    def get_cumulative_cost(self) -> float:
        """Return total cost accumulated."""

    def supports_native_git(self) -> bool:
        """Return True if agent handles its own commits."""
```

## How do I build an agent directly?

Most of the time the config picks the agent. To construct one yourself:

```python
from kapso.execution.coding_agents.factory import CodingAgentFactory

config = CodingAgentFactory.build_config(
    agent_type="claude_code",
    model="claude-opus-5",
)

agent = CodingAgentFactory.create(config)
agent.initialize("/path/to/workspace")

result = agent.generate_code("Implement a sorting algorithm")
print(f"Files changed: {result.files_changed}")
print(f"Cost: ${result.cost:.4f}")
```

`CodingAgentFactory.list_available()` returns the registered agent names.

## Claude Code

Anthropic's CLI, and what both shipped config modes use. Best on complex refactoring and planning, with MCP tool support.

```bash
npm install -g @anthropic-ai/claude-code
```

```yaml
coding_agent:
  type: "claude_code"
  model: "claude-opus-5"
  agent_specific:
    auth_mode: "oauth"
    claude_md_path: "CLAUDE.md"
```

### How do I authenticate Claude Code?

`auth_mode` accepts three values:

| Mode | Credential source | Behavior |
|------|-------------------|----------|
| `oauth` | `claude auth login`, or `CLAUDE_CODE_OAUTH_TOKEN` | Uses the current user's Claude CLI subscription login |
| `api_key` | `ANTHROPIC_API_KEY` | Requires direct Anthropic API credentials |
| `auto` | Either of the above | Takes whichever is present |

The shipped config sets `oauth` on every Claude Code block, and the low-level adapter defaults to `auto`. For a non-interactive environment set `CLAUDE_CODE_OAUTH_TOKEN` in `.env`.

An explicit mode removes higher-precedence credentials from the Claude subprocess environment, so `oauth` ignores an inherited `ANTHROPIC_API_KEY`. The parent process environment is never modified.

<Note>
  AWS Bedrock support was removed on 26 August 2026 in favour of a subscription-first setup. `auth_mode: bedrock` and the `use_bedrock` key are no longer accepted.
</Note>

## Codex

OpenAI's CLI, run non-interactively with a full-access sandbox. This is what [`inference`](/docs/reference/configuration#inference) uses for research, judging and utility calls.

```bash
npm install -g @openai/codex
codex login
```

```yaml
coding_agent:
  type: "codex"
  model: "gpt-5.6-sol"
```

Set `CODEX_API_KEY` in `.env` instead of logging in for a non-interactive environment.

## Gemini

Google's SDK, via `pip install google-generativeai`. Fast and cost-effective for iterative refinement.

```yaml
coding_agent:
  type: "gemini"
  model: "gemini-2.5-flash"
  debug_model: "gemini-2.5-flash"
```

Set `GOOGLE_API_KEY` in `.env`.

## OpenHands

Sandboxed, Docker-backed execution with full system access inside the sandbox.

<Warning>
  OpenHands conflicts with the `aider` extra on `litellm`, `openai` and `cffi`. Install it in a separate environment, never alongside `leeroo-kapso[aider]`.
</Warning>

```bash
conda create -n openhands_env python=3.12
conda activate openhands_env
pip install openhands-ai litellm
```

```yaml
coding_agent:
  type: "openhands"
  model: "gpt-4.1-mini"
  agent_specific:
    max_iterations: 30
```

## OSS Claude Code

The Claude Code CLI pointed at an open-source model over an Anthropic-compatible endpoint, such as GLM on Fireworks. Same CLI, different backend.

```yaml
coding_agent:
  type: "oss_claude_code"
  model: "accounts/fireworks/models/glm-5p2"
```

## CodingResult

All agents return a standardized result:

```python
@dataclass
class CodingResult:
    success: bool           # Whether generation succeeded
    output: str             # Agent's response text
    files_changed: List[str]  # Modified files
    error: Optional[str]    # Error message if failed
    cost: float             # Cost in dollars
    commit_message: Optional[str]  # Agent-generated message
    metadata: Dict[str, Any]  # Agent-specific data
```

## What must an agent return?

When used with `kapso.evolve()`, the coding agent must end its response with XML tags:

```xml
<code_changes_summary>Brief description of changes made</code_changes_summary>
<evaluation_script_path>kapso_evaluation/evaluate.py</evaluation_script_path>
<evaluation_output>Full output from running evaluation</evaluation_output>
<score>0.92</score>
<technical_difficulties>Anything that blocked or degraded the work</technical_difficulties>
```

The search strategy extracts these tags (`score` becomes a float; `null` or an empty value becomes `None`) and hands them to the feedback generator to validate the evaluation and decide whether to continue. There is no fallback format: output without the tags is a warning and an empty result.

### Example agent output

```text
I've implemented the random forest classifier. Here's what I did:

1. Created main.py with the classifier implementation
2. Added data loading and preprocessing
3. Created kapso_evaluation/evaluate.py to test accuracy

<code_changes_summary>Implemented random forest classifier with
GridSearchCV for hyperparameter tuning. Added cross-validation and
accuracy reporting.</code_changes_summary>
<evaluation_script_path>kapso_evaluation/evaluate.py</evaluation_script_path>
<evaluation_output>Loading data...
Training model...
Accuracy: 0.92</evaluation_output>
<score>0.92</score>
<technical_difficulties>none</technical_difficulties>
```

## How does the feedback generator use an agent?

Coding agents also power the feedback generator. The default feedback generator uses `claude_code`, but any agent can be used:

```python
from kapso.execution.search_strategies.generic.feedback_generator.feedback_generator import (
    FeedbackGenerator,
)
from kapso.execution.coding_agents.factory import CodingAgentFactory

# Use gemini for feedback generation
config = CodingAgentFactory.build_config(
    agent_type="gemini",
    model="gemini-2.0-flash",
)

feedback_gen = FeedbackGenerator(coding_agent_config=config)
```

## CodingAgentConfig

Configuration passed to agents:

```python
@dataclass
class CodingAgentConfig:
    agent_type: str         # "claude_code", "codex", etc.
    model: str              # Primary model
    debug_model: str        # Model for debugging
    workspace: str = ""     # Working directory
    use_git: bool = True    # Git integration
    agent_specific: Dict[str, Any] = field(default_factory=dict)
```

## How do I add my own agent?

```python
from kapso.execution.coding_agents.base import CodingAgentInterface, CodingResult
from kapso.execution.coding_agents.factory import CodingAgentFactory

class MyCustomAgent(CodingAgentInterface):
    def initialize(self, workspace: str) -> None:
        self.workspace = workspace
        # Setup agent

    def generate_code(self, prompt: str, debug_mode: bool = False) -> CodingResult:
        # Generate code
        model = self.config.debug_model if debug_mode else self.config.model

        # Call your API
        response = my_api.generate(prompt, model=model)

        # Track cost
        self._cumulative_cost += response.cost

        return CodingResult(
            success=True,
            output=response.text,
            files_changed=response.files,
            cost=response.cost,
        )

    def cleanup(self) -> None:
        # Clean up resources
        pass

    def supports_native_git(self) -> bool:
        return False  # Let ExperimentSession handle commits


CodingAgentFactory.register("my_custom_agent", MyCustomAgent)
```

Registration is a classmethod call, not a decorator. Agents declared in `agents.yaml` are registered on module import; `register()` is how you add one at runtime.

## How is Git handled?

Two ways, and the agent declares which by returning from `supports_native_git()`:

| Returns | Meaning |
|---------|---------|
| `True` | The agent commits its own changes |
| `False` | `ExperimentSession` commits after generation |

```python
def supports_native_git(self) -> bool:
    return False  # let ExperimentSession handle commits
```

Every shipped agent returns `False` except `aider`, which auto-commits.

## What capabilities does an agent report?

```python
def get_capabilities(self) -> Dict[str, bool]:
    return {
        "native_git": self.supports_native_git(),
        "sandbox": False,
        "planning_mode": False,
        "cost_tracking": True,
        "streaming": False,
    }
```
