`OrchestratorAgent` runs the experiment loop. It asks the search strategy for a candidate, hands it to a coding agent, runs the evaluation, and asks the feedback generator whether to continue — tracking the budget across the whole campaign.

## What does the orchestrator do?

1. **Budget Tracking**: Monitor time, iterations, and cost
2. **Context Gathering**: Assemble problem + KG + history
3. **Search Coordination**: Run search strategy iterations
4. **Stop Checking**: Check if feedback generator decided to stop
5. **Resource Cleanup**: Close connections when done

## How do I run one?

### Via Kapso API (recommended)

```python
from kapso import Kapso, Budget

kapso = Kapso()
solution = kapso.build(
    "Build a classifier with accuracy > 0.9",
    budget=Budget(experiments=10),
)

# Check if goal was achieved
if solution.goal_achieved:
    print(f"Goal achieved with score: {solution.score}")
```

### Direct usage

```python
from kapso.execution.orchestrator import OrchestratorAgent
from kapso.environment.handlers.generic import GenericProblemHandler

# Create problem handler
handler = GenericProblemHandler(
    problem_description="Build a classifier with accuracy > 0.9",
)

# Create orchestrator — config_path=None uses the packaged config
orchestrator = OrchestratorAgent(
    problem_handler=handler,
    coding_agent="claude_code",
    goal="Build a classifier with accuracy > 0.9",
)

# Run experimentation — returns a SolveResult
result = orchestrator.solve(
    experiment_max_iter=10,
    time_budget_minutes=60,
    cost_budget=50.0,
)

print(result.stopped_reason)   # "goal_achieved" | "max_iterations" | "budget_exhausted" | "cost_budget_exhausted" | "waiting_for_user"
best = result.best_experiment
```

## What happens in one iteration?

```python
# Faithful sketch of OrchestratorAgent.solve()
budget = BudgetSpec.resolve(config_block, time_budget_minutes, cost_budget, ...)

for i in range(experiment_max_iter):
    budget_progress = budget.progress(elapsed_seconds, i, ledger.total_cost())
    if budget_progress >= 100:
        break                     # checkpoint stays status="running", last_stop says why

    # Context is the handler's problem statement plus the previous
    # iteration's feedback; experiment history reaches the agent via
    # MCP tools, not the prompt.
    context = problem
    if self.current_feedback:
        context += f"\n\n## Feedback from Previous Iteration\n\n{self.current_feedback}"

    # One search iteration: ideation, implementation, judged feedback
    node = self.search_strategy.run(context, budget_progress)

    # A stop vote ends the campaign only where the strategy honours one:
    # the benchmark runners switch it off, open-ended maximization has no
    # "goal achieved"
    if node.should_stop and self.strategy_params["honor_agent_stop"]:
        break

    self._save_run_checkpoint(...)  # atomically, at the iteration boundary

return SolveResult(best_experiment=self.search_strategy.get_deliverable_experiment(), ...)
```

## How is the budget tracked?

The orchestrator tracks three budgets:

| Budget | Description | Progress Calculation |
|--------|-------------|---------------------|
| **Time** | Wall-clock time | `elapsed / time_budget` |
| **Iterations** | Experiment count | `i / max_iterations` |
| **Cost** | Metered spend from the `BudgetLedger` | `ledger.total_cost() / cost_budget` |

Budget progress is the **maximum** of all three:

```python
budget_progress = max(time_progress, iteration_progress, cost_progress) * 100
```

When any budget reaches 100%, the loop stops.

## How are components created?

The orchestrator creates components from configuration:

### Search strategy

```python
def _create_search_strategy(self, workspace_dir, start_from_checkpoint):
    # The implementation role over the hosts table: the workspace's
    # sessions carry its host, model and settings
    role = resolve_role(self.config["hosts"], self.strategy_params, "implementation")
    coding_agent_config = CodingAgentFactory.session_config(role, {})

    # Create via factory
    return SearchStrategyFactory.create(
        strategy_type=self.strategy_type,
        problem_handler=self.problem_handler,
        llm=self.llm,
        coding_agent_config=coding_agent_config,
        hosts=self.config["hosts"],
        params=self.strategy_params,
        workspace_dir=workspace_dir,
        start_from_checkpoint=start_from_checkpoint,
        ...
    )
```

### Knowledge search

```python
# The knowledge search is what the build loads: a loaded index's search
# (the experience package builds it), else the null search
self.knowledge_search = (
    knowledge_search if knowledge_search is not None else KnowledgeSearchFactory.create_null()
)
```

## Cost tracking

Every component reports into one `BudgetLedger`: the inference meter, the coding-agent sessions, and per-node phase telemetry all record against it, and `get_cumulative_cost()` returns `self.budget_ledger.total_cost()`. There is no per-component summing to drift out of agreement.

The run checkpoint carries the totals across a restart. A heartbeat (`budget.checkpoint_heartbeat_seconds`) and a run that raises both write the clock and the spend without touching the search state, so a round that dies midway is redone and what its finished sessions paid still counts against `cost_budget`. A coding-agent session reports its cost when it ends, so the cost of a session still running when the process is killed is not on the ledger.

## What gets cleaned up?

The orchestrator cleans up resources in a `finally` block:

```python
try:
    # Solve loop
    ...
finally:
    # Close knowledge search (only if the orchestrator created it)
    if self._owns_knowledge_search:
        self.knowledge_search.close()
```

## Configuration

The orchestrator loads the config with `load_config(config_path)`: the
packaged defaults with your override file over them, an unknown key refused
by name. The build's sessions are the roles under `search_strategy.params`,
each resolving to a host of the `hosts` table:

```yaml
# kapso-config.yaml, an override file over the packaged config
hosts:
  claude_code:
    model: claude-opus-5
    auth_mode: oauth
  codex:
    model: gpt-5.6-sol
    effort: xhigh

search_strategy:
  type: generic
  params:
    host: claude_code
    ideation:
      gates: [research, experiment_history, repo_memory]
    implementation:
      cli: codex
      gates: [research, repo_memory]
    judge: {}
    gate_failure_policy: warn

retry:
  max_attempts: 2
  initial_delay_seconds: 5
  max_delay_seconds: 60
  multiplier: 2
  jitter: true
```

See [Configuration](/docs/reference/configuration).

## Constructor parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| `problem_handler` | `ProblemHandler` | Handles problem context |
| `config_path` | `str` | Your override file over the packaged config; `None` is the packaged defaults |
| `coding_agent` | `str` | The host every role without a `cli` of its own runs on (`search_strategy.params.host`) |
| `knowledge_search` | `KnowledgeSearch` | The loaded index's search; `None` is the null search |
| `workspace_dir` | `str` | Custom workspace directory |
| `initial_repo` | `str` | Starting repo (local path or GitHub URL) |
| `goal` | `str` | The campaign goal, fingerprinted into the checkpoint |
| `resume` | `bool` | Continue from the workspace's run checkpoint |
| `eval_dir` / `data_dir` | `str` | Caller-owned evaluation and data directories |
| `iteration_evaluator` | `IterationEvaluator` | Optional [external evaluator](/docs/evolve/external-evaluation) |
| `strategy_params_overrides` | `dict` | Per-campaign overrides merged over `search_strategy.params` (the facade threads the bank serving this way) |
| `harness` | `Harness` | The loaded harness, staged into every session |
| `experience` | `list[dict]` | The loaded sources, as records |
